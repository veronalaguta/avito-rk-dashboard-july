### Исправление анализа превью

Уточнено правило: превью оцениваем только по CTR, потому что превью влияет на переход из показа в просмотр.

Правильная метрика:
- CTR превью = просмотры / показы.

Из анализа превью убраны:
- контакты;
- CR в контакт;
- цена контакта;
- звонки;
- заказы;
- цена заказа.

### Уточнение по контактам в превью-блоке

Правило уточнено после повторного обсуждения: в карточке превью нужно показывать не только CTR, но и контакты, CR в контакт и цену контакта.

Разделение такое:
- CTR оценивает прямой эффект превью: показ → просмотр;
- контакты и CR в контакт оценивают, как дальше отрабатывает связка превью + заголовок + текст + цена + гео.

Это нужно, чтобы видеть не только кликабельные картинки, но и связки, которые реально дают обращения.

### Перестроена логика аккаунтного анализа

Блок в аккаунтах больше не трактуется как `анализ первых превью и контактов`.

Новая структура:
- `Превью: первое фото` — агрегируем объявления по первому фото и смотрим, как они отработали;
- `Связки: город + превью + заголовок + текст` — анализируем уже конкретную связку объявления.

Для Орлова собран полный датасет:
- 171 объявление из Avito Pro;
- 166 объявлений сматчены с XML и первым фото;
- 35 групп по первому фото;
- 166 связок город + превью + заголовок + текст.

### Проблема одинаковых превью

Было замечено, что визуально одинаковые превью показывались отдельными карточками.

Причина: группировка шла по локальному пути картинки, а не по визуальной идентичности. Одна и та же картинка могла быть скачана под разными именами для разных объявлений.

Исправление:
- добавлен ручной `previewKey` для пилотного набора;
- группировка теперь идет по `previewKey`, если он указан.

Следующее более правильное решение:
- группировать по каноническому URL первого изображения;
- либо скачивать картинки и считать perceptual hash.
